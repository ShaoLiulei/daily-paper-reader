## 摘要
以 DeepSeek 稀疏注意力 (DSA) 为代表的词元级稀疏注意力机制，通过轻量级索引器对每个查询的所有历史键进行评分来实现细粒度的键选择，随后仅在选定的子集上计算注意力。虽然下游稀疏注意力本身具有良好的扩展性，但索引器仍需为每个查询扫描整个前缀，从而引入了随上下文长度增加而变得难以承受的逐层瓶颈。我们提出了 HISA（层级索引稀疏注意力），这是一种索引器的即插即用替代方案，它将搜索路径从扁平的词元扫描重写为两阶段层级过程：(1) 块级粗筛选阶段，通过对池化后的块表示进行评分来剔除无关区域；(2) 词元级精炼阶段，仅在保留的候选块内应用原始索引器。HISA 保留了下游 Sparse MLA 算子所使用的完全相同的词元级 Top-稀疏模式，且无需额外训练。在算子级基准测试中，HISA 在 64K 上下文下实现了显著加速。在“大海捞针” (Needle-in-a-Haystack) 和 LongBench 测试中，我们在无需任何微调的情况下，直接将 DeepSeek-V3.2 和 GLM-5 中的索引器替换为 HISA 索引器。实验表明，HISA 在质量上与原始 DSA 相当，同时性能大幅优于块稀疏基准方案。

## Abstract
Token-level sparse attention mechanisms, exemplified by DeepSeek Sparse Attention (DSA), achieve fine-grained key selection by scoring every historical key for each query through a lightweight indexer, then computing attention only on the selected subset. While the downstream sparse attention itself scales favorably, the indexer must still scan the entire prefix for every query, introducing an per-layer bottleneck that grows prohibitively with context length. We propose HISA (Hierarchical Indexed Sparse Attention), a plug-and-play replacement for the indexer that rewrites the search path from a flat token scan into a two-stage hierarchical procedure: (1) a block-level coarse filtering stage that scores pooled block representations to discard irrelevant regions, followed by (2) a token-level refinement stage that applies the original indexer exclusively within the retained candidate blocks. HISA preserves the identical token-level top-sparse pattern consumed by the downstream Sparse MLA operator and requires no additional training. On kernel-level benchmarks, HISA achieves up to speedup at 64K context. On Needle-in-a-Haystack and LongBench, we directly replace the indexer in DeepSeek-V3.2 and GLM-5 with our HISA indexer, without any finetuning. HISA closely matches the original DSA in quality, while substantially outperforming block-sparse baselines.

### 论文总结：HISA (Hierarchical Indexed Sparse Attention)

#### 1. 核心问题与整体含义（研究动机和背景）
随着大语言模型（LLM）上下文窗口从 128K 扩展至 1M 以上，自注意力机制的平方级计算开销成为瓶颈。DeepSeek-V3.2 等模型采用了**词元级稀疏注意力（DSA）**，通过轻量级索引器为每个 Query 筛选 Top-k 个 Token 进行计算。
然而，作者发现了一个被忽视的瓶颈：**索引器本身仍需扫描整个前缀序列**。即使下游注意力计算变稀疏了，索引阶段依然存在 $O(L^2)$ 的逐层开销。在超长文本场景下，索引器的耗时甚至会超过注意力计算本身。HISA 的目标是在不改变最终稀疏模式的前提下，通过优化搜索路径来消除这一瓶颈。

#### 2. 论文提出的方法论：核心思想与关键技术
HISA 提出了一种**两阶段层级搜索路径**，作为 DSA 索引器的即插即用替代方案：
*   **块级粗筛选（Stage 1）**：将前缀序列划分为大小为 $B$ 的连续块。对每个块内的索引键进行均值池化（Mean Pooling），生成块代表向量。Query 首先对这些块代表向量进行评分，仅保留 Top-$m$ 个最相关的块。为了保证稳定性，第一块（包含 Attention Sink）和最后一块（局部上下文）会被强制保留。
*   **词元级精炼（Stage 2）**：在保留的 $m$ 个候选块内，应用原始的 DSA 词元级索引机制进行精细评分，最终选出 Top-$k$ 个 Token。
*   **算法流程**：
    1. 维护块级池化键（可增量更新）。
    2. 计算 Query 与块代表向量的得分，筛选候选块集合 $\Omega_t$。
    3. 在 $\Omega_t$ 中进行词元级评分，输出最终的 Token 索引集 $T_t$。
    4. 将 $T_t$ 传递给原有的 Sparse MLA 算子。
*   **复杂度优化**：将每层索引开销从 $O(L^2)$ 降低到 $O(L^2/B + LmB)$。

#### 6. 主要结论与发现
*   **效率提升**：在 64K 上下文下，HISA 索引内核相比 DSA 实现了 **2.16× 至 3.75× 的加速**。

#### 7. 优点
*   **即插即用**：无需重新训练模型，无需修改 KV Cache 布局，直接替换索引模块即可生效。
*   **算法兼容性**：完美适配 DeepSeek 的 Sparse MLA 架构，解决了长文本推理中被忽视的索引瓶颈。
*   **硬件友好**：利用块级操作和 TileLang 优化，充分发挥了 GPU 的并行计算能力。

*   **信息丢失风险**：均值池化可能会掩盖块内极少数但极关键的 Token（Salient Outliers）。
*   **边界处理**：当重要信息跨越块边界时，简单的块划分可能导致评分偏差（作者建议未来可尝试重叠块或自适应边界）。
*   **系统集成**：目前主要展示了内核级加速，在复杂的连续批处理（Continuous Batching）和投机采样等端到端系统环境下的实际吞吐提升仍需进一步验证。
