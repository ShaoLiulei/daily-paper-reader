## 摘要
蒙特卡洛树搜索 (MCTS) 是一种有效的测试时计算扩展 (TTCS) 方法，用于提升大语言模型的推理性能，但其高度多变的执行时间在实践中导致了严重的长尾延迟。现有的优化方法（如正向提前退出）在有利情况下可以降低延迟，但在搜索持续进行却无实质性进展时效果较差。我们引入了“负向提前退出”（negative early exit），用于剪除无成效的 MCTS 轨迹，以及一种“自适应增强机制”（adaptive boosting mechanism），通过重新分配回收的计算资源来减少并发搜索之间的资源竞争。这些技术集成到 vLLM 中后，在保持推理准确性的同时，显著降低了 p99 端到端延迟并提高了吞吐量。

## Abstract
Monte Carlo Tree Search (MCTS) is an effective test-time compute scaling (TTCS) method for improving the reasoning performance of large language models, but its highly variable execution time leads to severe long-tail latency in practice. Existing optimizations such as positive early exit, reduce latency in favorable cases but are less effective when search continues without meaningful progress. We introduce {\it negative early exit}, which prunes unproductive MCTS trajectories, and an {\it adaptive boosting mechanism} that reallocates reclaimed computation to reduce resource contention among concurrent searches. Integrated into vLLM, these techniques substantially reduce p99 end-to-end latency while improving throughput and maintaining reasoning accuracy.

#### 1. 核心问题与整体含义（研究动机和背景）
论文关注的是大语言模型（LLM）在推理阶段的**测试时计算扩展（Test-time Compute Scaling, TTCS）**。虽然蒙特卡洛树搜索（MCTS）在复杂推理任务中比传统的并行采样（如 Best-of-N）更有效，但其**串行执行特性**导致了严重的性能瓶颈：
*   **长尾延迟（Tail Latency）**：MCTS 的搜索深度和执行时间极度不确定，少数复杂请求会长时间占用系统资源。
*   **资源浪费**：现有的“正向早停”机制只能在找到好答案时停止，但当搜索陷入僵局（无进展）时，系统仍会耗尽所有预算，造成无效计算。
*   **并行度不足**：传统的 MCTS 难以在保持搜索质量的同时实现高效的并行化。

#### 2. 方法论：核心思想与关键技术
本文提出了一套自适应并行 MCTS 框架，核心思想是将 MCTS 视为一个需要主动资源管理的系统，而非单纯的搜索算法。

*   **负向早停（Negative Early Exit, NE）**：
    *   **原理**：基于过程奖励模型（PRM）的特性，如果当前搜索树中所有叶节点的得分都低于某个阈值（即“徒劳”状态），则判定该请求无法在预算内找到解，立即终止搜索。
    *   **优化**：引入“选择性徒劳检查”，利用第一步奖励与最终得分的相关性，排除低潜力分支，提高剪枝效率。
*   **自适应增强机制（Adaptive Boosting）**：
    *   **动态并行度控制**：根据任务的“资历”（等待时间）和“紧急程度”（得分接近阈值的程度）计算优先级分数 $S(i, t)$。
    *   公式：$S(i, t) = \log(1 + \Delta t_i) + \beta \cdot I(\rho_i > \tau)$，其中 $\Delta t_i$ 是耗时，$\rho_i$ 是进度比。
    *   **资源重分配**：将负向早停释放的计算资源动态分配给那些即将完成（90% 接近阈值）的任务，通过提高并行度（DOP）加速其完成。
*   **并行 MCTS 策略（WU-PUCT）**：
    *   改进了 AlphaZero 的 PUCT 规则，引入“未观测计数”（Unobserved Counts）来惩罚正在被其他 worker 探索的节点，防止并行搜索时的“探索崩溃”。

#### 7. 优点（亮点）
*   **系统级创新**：不只是改进搜索算法，而是从调度和资源分配的角度解决 LLM 推理的工程痛点。
*   **实用性强**：直接集成于 vLLM，对于需要大规模部署推理服务的厂商具有很高的参考价值。
*   **双向早停**：首次在 TTCS 领域系统性地结合了正向和负向早停，完善了搜索退出的逻辑闭环。

*   **并行开销**：在某些简单任务（如 Qwen 处理 AMC23）中，过度并行化带来的调度开销反而可能导致吞吐量轻微下降。
