## 摘要
大语言模型（LLM）在实际服务中表现出强大的性能，但同时也带来了高昂的推理成本，尤其是在跨用户和会话存在重复或近乎重复查询的工作负载下。在这项工作中，我们提出了 MemBoost，这是一种记忆增强的 LLM 服务框架，它使轻量级模型能够重用先前生成的答案并检索相关的支持信息以进行低成本推理，同时选择性地将困难或不确定的查询升级到更强大的模型。与主要为单次响应提供依据的标准检索增强生成（RAG）不同，MemBoost 专为交互式场景设计，支持答案重用、记忆持续增长和成本感知路由。在模拟工作负载下针对多个模型的实验表明，MemBoost 显著减少了昂贵的大模型调用次数和整体推理成本，同时保持了与强模型基准相当的高回答质量。

## Abstract
Large Language Models (LLMs) deliver strong performance but incur high inference cost in real-world services, especially under workloads with repeated or near-duplicate queries across users and sessions. In this work, we propose MemBoost, a memory-boosted LLM serving framework that enables a lightweight model to reuse previously generated answers and retrieve relevant supporting information for cheap inference, while selectively escalating difficult or uncertain queries to a stronger model. Unlike standard retrieval-augmented generation, which primarily grounds a single response, MemBoost is designed for interactive settings by supporting answer reuse, continual memory growth, and cost-aware routing. Experiments across multiple models under simulated workloads show that MemBoost substantially reduces expensive large-model invocations and overall inference cost, while maintaining high answer quality comparable to the strong model baseline.

### 1. 核心问题与研究动机
*   **核心问题**：在实际的 LLM 服务中，大量用户查询存在**重复或语义近似**的现象。直接调用昂贵的顶级大模型（如 GPT-4 级别）处理这些冗余请求会导致极高的计算成本和延迟。
*   **研究动机**：现有的检索增强生成（RAG）主要关注知识接地（Grounding），而语义缓存（Semantic Caching）通常与生成模型解耦。论文旨在建立一个统一的框架，让轻量级模型能够自主决定是“复用记忆中的旧答案”还是“升级（Escalate）给强模型处理”，从而在保证质量的前提下大幅降低推理成本。

### 2. 方法论与核心架构
MemBoost 框架由三个核心组件构成，形成“检索 -> 决策 -> 升级 -> 回写”的闭环：
*   **关联记忆引擎 (AME)**：存储历史查询、对应答案及元数据。使用向量嵌入（Embedding）技术支持快速的语义检索。
*   **大语言模型专家 (Oracle)**：高性能但高成本的顶级模型（如 Qwen3-14B），作为处理复杂问题的兜底方案。
*   **元控制器 (MC)**：一个轻量级 LLM（如 2B-4B 规模），负责调度。
    *   **流程**：MC 接收查询后，先从 AME 检索 $K$ 个候选条目。
    *   **决策**：MC 判断检索内容是否足以回答问题。若是，则直接生成答案；若不足或不确定，则调用 Oracle。
    *   **回写机制**：当 Oracle 生成新答案后，MC 评估其价值并决定是否将其存入 AME，实现记忆的持续增长。
*   **成本模型**：系统目标是最小化总成本 $C_T$，其中 Oracle 调用成本 $c_O$ 远大于 MC 成本 $c_M$ 和检索成本 $c_R$。

### 3. 实验设计
*   **数据集**：使用 **MMLU-Pro**（商业类别），这是一个比标准 MMLU 更具挑战性的多任务理解基准。
*   **模拟场景**：为了模拟真实世界中查询的重复性，研究者使用 **Zipf 分布**（齐夫定律）采样查询流，设置了不同的偏斜参数 $\alpha$（0.8, 1.1, 1.4），$\alpha$ 越大代表重复率越高。
*   **对比基准 (Baselines)**：
    *   **独立小模型**：Qwen3.5-2B, Ministral-3B, Qwen3-4B。
    *   **独立大模型 (Oracle)**：Qwen3-14B。
*   **评估指标**：回答准确率（Accuracy）、内存使用率（即节省 Oracle 调用的比例）、响应延迟（Latency）。

### 4. 资源与算力
*   **硬件设备**：实验使用了 **NVIDIA A100 80GB GPU**。
*   **部署细节**：为了公平比较推理时间，元控制器（含小模型和 AME）与 Oracle 分别部署在独立的 A100 GPU 上。
*   **推理框架**：使用 **vLLM** 库进行推理优化，以提高吞吐量。
*   **训练时长**：文中未提及模型微调或训练时长，主要侧重于推理阶段的系统框架表现。

### 5. 实验数量与充分性
*   **实验规模**：进行了 5,000 步的连续查询流模拟。
*   **维度覆盖**：涵盖了 3 种不同规模的元控制器模型、3 种不同重复率的负载分布。
*   **充分性评价**：实验设计较为客观，通过 Zipf 分布成功模拟了生产环境的负载特征。对比了准确率与成本（延迟/调用率）的双重维度，证明了框架的有效性。但实验主要集中在选择题形式的 MMLU-Pro 上，缺乏对长文本生成或代码任务的验证。

### 6. 主要结论与发现
*   **性能持平甚至超越**：MemBoost 在所有设定下均显著优于小模型基准，且准确率与 Oracle 相当。在某些高重复率场景下，MemBoost (2B) 甚至超过了 Oracle，因为它可以直接复用经过验证的正确历史答案，避免了随机生成误差。
*   **成本大幅降低**：随着时间推移，AME 逐渐积累知识，Oracle 的调用率显著下降，系统响应延迟也随之稳步降低。
*   **负载敏感性**：工作负载越集中（重复率越高），MemBoost 的优势越明显。

### 7. 优点与亮点
*   **闭环学习**：引入了“回写”机制，使系统具备持续学习和自我进化的能力，无需重新训练模型。
*   **灵活路由**：将推理视作“检索或升级”的决策问题，充分发挥了大小模型的各自优势。
*   **实用性强**：直接针对工业界关注的“推理成本”痛点，且对现有 RAG 和缓存技术做了有机整合。

### 8. 不足与局限
*   **任务多样性不足**：目前仅在选择题数据集上验证，未测试开放式问答、长文本摘要或复杂编程任务，这些任务的“语义相似度”判定更难。
*   **检索风险**：在处理“语义相似但答案不同”的微小差异查询（Paraphrased queries）时，可能存在误匹配（False Hit）风险，导致返回错误答案。
*   **静态评估**：实验基于固定基准的重复采样，未考虑真实动态环境中知识过时（Stale knowledge）和记忆清理（Eviction）的复杂策略。
