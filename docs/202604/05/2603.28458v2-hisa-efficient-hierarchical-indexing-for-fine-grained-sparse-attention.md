## 摘要
以 DeepSeek 稀疏注意力 (DSA) 为代表的词元级 (Token-level) 稀疏注意力机制，通过轻量级索引器为每个查询 (query) 对所有历史键 (key) 进行评分，从而实现细粒度的键选择，随后仅在选定的子集上计算注意力。尽管下游的稀疏注意力本身具有良好的扩展性，但索引器仍需为每个查询扫描整个前缀，这引入了随上下文长度增加而变得难以承受的逐层瓶颈。我们提出了 HISA（分层索引稀疏注意力），这是一种索引器的即插即用替代方案，它将搜索路径从扁平的词元扫描重写为两阶段的分层过程：(1) 块级粗过滤阶段，通过对池化后的块表示进行评分来剔除无关区域；随后是 (2) 词元级精炼阶段，仅在保留的候选块内应用原始索引器。HISA 保留了下游 Sparse MLA 算子所使用的完全相同的词元级 Top-稀疏模式，且无需额外训练。在算子级基准测试中，HISA 在 64K 上下文下实现了显著加速。在“大海捞针” (Needle-in-a-Haystack) 和 LongBench 测试中，我们在无需任何微调的情况下，直接将 DeepSeek-V3.2 和 GLM-5 中的索引器替换为我们的 HISA 索引器。HISA 在质量上与原始 DSA 紧密匹配，同时性能大幅优于块稀疏 (block-sparse) 基准方案。

## Abstract
Token-level sparse attention mechanisms, exemplified by DeepSeek Sparse Attention (DSA), achieve fine-grained key selection by scoring every historical key for each query through a lightweight indexer, then computing attention only on the selected subset. While the downstream sparse attention itself scales favorably, the indexer must still scan the entire prefix for every query, introducing an per-layer bottleneck that grows prohibitively with context length. We propose HISA (Hierarchical Indexed Sparse Attention), a plug-and-play replacement for the indexer that rewrites the search path from a flat token scan into a two-stage hierarchical procedure: (1) a block-level coarse filtering stage that scores pooled block representations to discard irrelevant regions, followed by (2) a token-level refinement stage that applies the original indexer exclusively within the retained candidate blocks. HISA preserves the identical token-level top-sparse pattern consumed by the downstream Sparse MLA operator and requires no additional training. On kernel-level benchmarks, HISA achieves up to speedup at 64K context. On Needle-in-a-Haystack and LongBench, we directly replace the indexer in DeepSeek-V3.2 and GLM-5 with our HISA indexer, without any finetuning. HISA closely matches the original DSA in quality, while substantially outperforming block-sparse baselines.

#### 1. 核心问题与整体含义（研究动机和背景）
随着大语言模型（LLM）上下文窗口迈向 128K 甚至 1M 级别，传统的全量注意力计算（Dense Attention）因其二次方复杂度成为瓶颈。DeepSeek-V3.2 等模型引入了**词元级稀疏注意力（DSA）**，通过一个轻量级索引器为每个 Query 挑选最相关的 Top-k 个 Token 进行计算。
然而，作者发现了一个被忽视的瓶颈：**索引器本身仍需扫描整个前缀序列**。这意味着即使下游注意力计算是稀疏的，索引阶段依然存在 $O(L^2)$ 的逐层计算开销。在超长文本场景下，索引器的耗时甚至会超过注意力计算本身。HISA 的提出正是为了通过分层搜索路径解决这一索引瓶颈。

#### 2. 方法论：核心思想与技术细节
HISA 提出了一种**两阶段分层搜索策略**，将原本的“扁平化全量扫描”重写为“由粗到精”的过程：
*   **预处理（块池化）**：将前缀序列划分为大小为 $B$ 的连续块，对每个块内的索引键（Indexing Keys）进行均值池化（Mean Pooling），生成块代表向量。
*   **阶段一：块级粗过滤（Block-level Coarse Filtering）**：Query 首先对所有块代表向量进行评分，筛选出得分最高的 Top-m 个候选块。这一步将搜索范围从 $L$ 缩小到 $m \times B$。
*   **阶段二：词元级精炼（Token-level Refinement）**：仅在选定的候选块内部，应用原始 DSA 的索引机制对 Token 进行精确评分，最终选出 Top-k 个 Token 传递给下游的 Sparse MLA 算子。
*   **算法特性**：HISA 是**即插即用**的，不需要对模型进行重新训练或微调，也不改变 KV Cache 的布局，完全兼容 DeepSeek-V3.2 和 GLM-5 的架构。

#### 6. 主要结论与发现
*   **显著加速**：在 64K 上下文长度下，HISA 的索引内核相比原始 DSA 实现了 **2.16x 至 3.75x** 的加速。

#### 7. 优点（亮点）
*   **高效性**：将索引复杂度从 $O(L)$ 降至 $O(L/B + mB)$，解决了长文本下的二次方扩展难题。
*   **兼容性极强**：无需微调，直接替换现有模型的索引模块即可生效，对开发者非常友好。
*   **细粒度保留**：不同于粗糙的块稀疏，HISA 最终输出的仍是 Token 级别的稀疏模式，保留了模型原有的注意力精度。

#### 8. 不足与局限
*   **信息丢失风险**：均值池化可能会掩盖块内极少数但极其关键的 Token（Salient Outliers），虽然实验显示影响较小，但在极端语义边界情况下可能存在风险。
*   **超参数依赖**：性能和精度平衡依赖于 $B$ 和 $m$ 的选择，不同任务可能需要微调这些超参数。
*   **系统集成深度**：目前主要展示了内核级和基准测试结果，在复杂的生产环境（如持续批处理 Continuous Batching、推测解码等）中的端到端吞吐量表现仍需进一步验证。
