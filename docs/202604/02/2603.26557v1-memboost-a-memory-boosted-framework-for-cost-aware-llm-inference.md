## 摘要
大语言模型（LLMs）表现出强大的性能，但在实际服务中会产生高昂的推理成本，特别是在跨用户和会话存在重复或近乎重复查询的工作负载下。在这项工作中，我们提出了 MemBoost，这是一个记忆增强的大语言模型服务框架，它使轻量级模型能够重用先前生成的答案并检索相关的支持信息以实现低成本推理，同时选择性地将困难或不确定的查询转发给更强大的模型。与主要为单个响应提供依据的标准检索增强生成（RAG）不同，MemBoost 通过支持答案重用、持续记忆增长和成本感知路由，专为交互式场景而设计。在模拟工作负载下针对多个模型的实验表明，MemBoost 显著减少了昂贵的大模型调用次数和整体推理成本，同时保持了与强模型基准相当的高回答质量。

## Abstract
Large Language Models (LLMs) deliver strong performance but incur high inference cost in real-world services, especially under workloads with repeated or near-duplicate queries across users and sessions. In this work, we propose MemBoost, a memory-boosted LLM serving framework that enables a lightweight model to reuse previously generated answers and retrieve relevant supporting information for cheap inference, while selectively escalating difficult or uncertain queries to a stronger model. Unlike standard retrieval-augmented generation, which primarily grounds a single response, MemBoost is designed for interactive settings by supporting answer reuse, continual memory growth, and cost-aware routing. Experiments across multiple models under simulated workloads show that MemBoost substantially reduces expensive large-model invocations and overall inference cost, while maintaining high answer quality comparable to the strong model baseline.

### 1. 核心问题与研究动机
*   **核心问题**：如何在保证大语言模型（LLM）服务质量的前提下，降低在处理现实世界中大量**重复或近似重复查询**时的高昂推理成本。
*   **研究背景**：目前的 LLM 部署面临“成本-质量”困境。虽然检索增强生成（RAG）能提供外部知识，但标准 RAG 侧重于单次查询的知识接地，缺乏对历史生成答案的复用机制。此外，现有系统往往在“小模型生成”与“大模型调用”之间缺乏灵活且具备成本感知的路由策略。

### 2. 方法论与核心技术
MemBoost 提出了一个“检索-决策-升级-回写”的闭环框架，包含三个核心组件：
*   **关联记忆引擎 (AME)**：存储历史查询、生成的答案及元数据。利用向量嵌入（Embedding）和向量数据库（FAISS）实现快速语义检索。
*   **元控制器 (MC)**：一个轻量级 LLM（如 2B-4B 规模），负责调度。它接收用户查询和 AME 检索到的候选条目，决定是直接复用记忆中的答案、基于记忆合成答案，还是将任务“升级”给强力模型。
*   **大模型专家 (Oracle)**：高性能但高成本的旗舰模型（如 14B 或更大），仅在 MC 认为记忆不足以回答时才被调用。
*   **工作流程**：
    1.  **检索**：AME 检索 K 个相似条目。
    2.  **决策与生成**：MC 判断是否可由记忆解决。若能，则输出；若不能，调用 Oracle。
    3.  **回写**：当 Oracle 生成新答案后，MC 决定是否将其存入 AME，实现记忆的持续增长。
*   **成本模型**：系统目标是最小化总成本 $C_T$，其中 Oracle 调用成本 $c_O$ 远大于 MC 成本 $c_M$ 和检索成本 $c_R$。

*   **对比基准 (Baselines)**：
    *   独立的小模型：Qwen3.5-2B, Ministral-3B, Qwen3-4B。
    *   独立的强模型 (Oracle)：Qwen3-14B。

### 6. 主要结论与发现
*   **性能持平甚至超越**：MemBoost 在大幅降低成本的同时，准确率达到了 Oracle 水平。在某些配置下（如配合 Qwen3.5-2B），其准确率甚至略高于 Oracle，这得益于对历史正确答案的稳定复用。
*   **成本与延迟显著下降**：随着记忆库的填充，Oracle 调用率持续降低，系统平均响应延迟随之线性下降。
*   **工作负载敏感性**：查询重复率越高（Zipf $\alpha$ 越大），MemBoost 的优势越明显。

### 7. 优点与亮点
*   **闭环学习**：引入了“回写机制”，使系统能够随着使用时间的增加而变得更聪明、更便宜。
*   **成本感知路由**：不同于简单的语义缓存，MC 能够根据检索质量动态决定是否升级，平衡了效率与精度。
*   **即插即用**：该框架不依赖于特定的模型架构，可以灵活更换 MC 或 Oracle 模型。

### 8. 不足与局限
*   **任务类型局限**：目前仅在 MMLU-Pro（选择题）上验证，未测试代码生成、长文创作等开放式任务，这些任务的语义相似度判定更难。
*   **语义冲突风险**：在处理“看似相似但答案迥异”的查询（Paraphrased queries）时，可能存在检索错误（False hits）导致误导性回答的风险。
*   **冷启动问题**：在系统运行初期或查询极其稀疏的场景下，MemBoost 的额外开销（MC 和检索）可能会使总成本略高于直接调用 Oracle。
