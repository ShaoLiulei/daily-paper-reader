## 摘要
大语言模型（LLM）的服务范式正迅速向复杂的多智能体工作流转变，其中专用智能体在海量共享上下文上进行协作。虽然低秩自适应（LoRA）能够在单个基础模型上高效地共同托管这些专用智能体，但它在服务过程中引入了关键的内存占用瓶颈。具体而言，独特的 LoRA 激活导致了不同智能体之间的键值（KV）缓存差异，使得传统的共享上下文前缀缓存失效。这迫使系统维护冗余的 KV 缓存，迅速使 GPU 容量饱和并降低吞吐量。为了应对这一挑战，我们推出了 ForkKV，这是一个针对多 LoRA 智能体工作流的服务系统，其核心是操作系统中一种新颖的内存管理范式：带有写时复制（CoW）的 fork。通过利用 LoRA 的结构特性，ForkKV 在物理上将 KV 缓存解耦为一个海量的共享组件（类似于父进程的内存页）和轻量级的智能体特定组件（子进程的页面）。为了支持这一机制，我们提出了一种 DualRadixTree 架构，允许新 fork 的智能体继承海量共享缓存，并对其轻量级的唯一缓存应用 CoW 语义。此外，为了保证高效执行，我们设计了 ResidualAttention，这是一种专门的算子，可直接在片上 SRAM 中重构解耦的 KV 缓存。在多种语言模型和不同任务的实际数据集上进行的全面评估表明，ForkKV 的吞吐量达到了最先进的多 LoRA 服务系统的 3.0 倍，且对生成质量的影响微乎其微。

## Abstract
The serving paradigm of large language models (LLMs) is rapidly shifting towards complex multi-agent workflows where specialized agents collaborate over massive shared contexts. While Low-Rank Adaptation (LoRA) enables the efficient co-hosting of these specialized agents on a single base model, it introduces a critical memory footprint bottleneck during serving. Specifically, unique LoRA activations cause Key-Value (KV) cache divergence across agents, rendering traditional prefix caching ineffective for shared contexts. This forces redundant KV cache maintenance, rapidly saturating GPU capacity and degrading throughput.   To address this challenge, we introduce ForkKV, a serving system for multi-LoRA agent workflows centered around a novel memory management paradigm in OS: fork with copy-on-write (CoW). By exploiting the structural properties of LoRA, ForkKV physically decouples the KV cache into a massive shared component (analogous to the parent process's memory pages) and lightweight agent-specific components (the child process's pages). To support this mechanism, we propose a DualRadixTree architecture that allows newly forked agents to inherit the massive shared cache and apply CoW semantics for their lightweight unique cache. Furthermore, to guarantee efficient execution, we design ResidualAttention, a specialized kernel that reconstructs the disaggregated KV cache directly within on-chip SRAM. Comprehensive evaluations across diverse language models and practical datasets of different tasks demonstrate that ForkKV achieves up to 3.0x the throughput of state-of-the-art multi-LoRA serving systems with a negligible impact on generation quality.

### 1. 核心问题与整体含义
*   **研究背景**：随着大语言模型（LLM）应用从简单对话转向复杂的多智能体工作流（如 Coding Assistant），多个专用智能体（Agent）通常需要在海量的共享上下文（如庞大的代码库或系统提示词）上协作。
*   **核心痛点**：为了兼顾效率与专业性，业界普遍采用 **Multi-LoRA** 架构（在共享基座模型上挂载多个轻量级适配器）。然而，传统的“前缀缓存（Prefix Caching）”技术在此时失效了——因为不同的 LoRA 适配器会产生独特的激活值，导致即使输入文本相同，生成的 KV Cache 也会发散。这迫使系统为每个智能体维护独立的、冗余的 KV Cache，迅速耗尽 GPU 显存，限制了系统的并发处理能力和吞吐量。
*   **论文目标**：在保证生成质量的前提下，消除多 LoRA 场景下的 KV Cache 冗余，实现显存占用的极大幅度压缩。

### 2. 方法论
ForkKV 借鉴了操作系统（OS）中进程创建的 **fork** 与 **写时复制（Copy-on-Write, CoW）** 机制，提出了一套解耦的内存管理范式：

*   **解耦 KV 缓存（Disaggregated KV Cache）**：
    *   利用 LoRA 的线性分解特性：$Y = xW + xAB$。
    *   将 KV Cache 拆分为两部分：**bCache**（Base Cache，即 $xW$，体积巨大且在所有智能体间共享）和 **rCache**（Residual Cache，即 $xA$，体积微小且特定于每个 LoRA 适配器）。
    *   数学上，bCache 占据了绝大部分空间（通常是 rCache 的数十倍），通过共享 bCache，显存占用可降低至接近 $1/N$。
*   **DualRadixTree 架构**：
    *   设计了双基数树结构：**Base RadixTree** 负责按 Token ID 索引共享的 bCache；**Residual RadixTree** 负责按 (Token ID, Agent ID) 索引私有的 rCache。
    *   **Fork 语义**：新智能体启动时，通过前缀匹配“继承”父节点的 bCache，并仅为自己的 rCache 分配空间。
*   **ResidualAttention 内核**：
    *   **片上重构**：为了避免在显存（HBM）中重构完整 KV Cache 带来的带宽开销，ForkKV 设计了专门的 Triton 算子，直接在 GPU 的 SRAM 中实时重构。
    *   **延迟 RoPE 与矩阵结合律**：利用矩阵乘法结合律 $\text{sm}(QK^T)(V_{base} + V_{res}B_v) = \text{sm}(QK^T)V_{base} + (\text{sm}(QK^T)V_{res})B_v$，将复杂的投影运算移出注意力机制的内循环，显著降低计算量。

### 6. 主要结论
*   **吞吐量提升**：在 ReAct 工作流中提升了 **1.25x - 3.04x**；在 MapReduce 工作流中提升了 **1.68x - 2.60x**。
*   **显存优化**：平均每个智能体的 KV Cache 内存占用降低了约 **12.7x**，使得系统能支持 32 倍以上的并发智能体。
*   **质量保持**：相比于完全共享 KV Cache 导致的 21% 精度崩塌，ForkKV 的 F1 分数平均仅下降 **0.71%**，输入状态相似度保持在 99.4% 以上。

### 7. 优点
*   **跨领域创新**：巧妙地将 OS 的内存管理思想（Fork/CoW）应用到 LLM 显存管理中，解决了 Multi-LoRA 场景下的结构性冗余。
*   **软硬协同优化**：不仅在管理层（DualRadixTree）做文章，还通过自定义 Triton 内核（ResidualAttention）解决了重构开销问题。
*   **精度与效率的平衡**：通过数学分解而非简单的近似，在极小精度损失下换取了巨大的性能增益。

### 8. 不足与局限
*   **低负载下的开销**：在并发量极低、显存充足时，由于解耦计算和重构的额外开销，ForkKV 的吞吐量可能略低于原生前缀缓存（论文中提到可通过动态切换策略缓解）。
*   **架构依赖**：该方法高度依赖于 LoRA 的线性结构，对于全参数微调或其他非线性适配器（如 Adapter 模块）可能不适用。
*   **长链误差风险**：虽然实验显示精度损失微小，但在极长链条的多智能体协作中，跨层共享带来的微小偏差是否会产生“蝴蝶效应”仍需更极端的测试。
