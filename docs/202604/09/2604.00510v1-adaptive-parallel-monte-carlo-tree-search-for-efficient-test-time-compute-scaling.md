## 摘要
蒙特卡洛树搜索 (MCTS) 是一种有效的测试时计算缩放 (TTCS) 方法，用于提升大语言模型的推理性能，但其高度多变的执行时间在实践中导致了严重的长尾延迟。现有的优化方法（如正向提前退出）在理想情况下可以降低延迟，但在搜索持续进行却无实质性进展时效果较差。我们引入了“负向提前退出”（negative early exit），用于剪枝无成效的 MCTS 轨迹，以及一种“自适应增强机制”（adaptive boosting mechanism），通过重新分配回收的计算资源来减少并发搜索间的资源竞争。这些技术集成到 vLLM 中后，在显著降低 p99 端到端延迟的同时，提升了吞吐量并保持了推理准确性。

## Abstract
Monte Carlo Tree Search (MCTS) is an effective test-time compute scaling (TTCS) method for improving the reasoning performance of large language models, but its highly variable execution time leads to severe long-tail latency in practice. Existing optimizations such as positive early exit, reduce latency in favorable cases but are less effective when search continues without meaningful progress. We introduce {\it negative early exit}, which prunes unproductive MCTS trajectories, and an {\it adaptive boosting mechanism} that reallocates reclaimed computation to reduce resource contention among concurrent searches. Integrated into vLLM, these techniques substantially reduce p99 end-to-end latency while improving throughput and maintaining reasoning accuracy.

*   **研究背景**：随着大语言模型（LLM）在复杂推理任务中的应用，测试时计算缩放（Test-time Compute Scaling, TTCS）成为提升性能的关键。蒙特卡洛树搜索（MCTS）因其能平衡探索与利用，在推理准确率上优于传统的并行候选扩展方法（如 Best-of-N）。
*   **核心问题**：MCTS 存在严重的**长尾延迟**和**资源浪费**问题。其固有的顺序执行特性导致推理时间随深度增加而剧增；此外，现有的“正向早停”（找到好答案就停止）无法处理那些“注定失败”的搜索路径，导致系统在无意义的计算上消耗大量资源，限制了其在生产环境中的部署。

#### 2. 论文提出的方法论
论文从系统架构的角度重新审视了 MCTS，提出了一个自适应并行框架，核心技术包括：
*   **WU-PUCT 并行策略**：扩展了 WU-UCT 算法，引入“未观察计数”（Unobserved Counts）来修正 PUCT 选择规则。通过考虑正在进行但尚未完成的 rollout 统计信息，防止多个并行 worker 冗余搜索同一路径。
*   **负向早停机制（Negative Early Exit, NE）**：
    *   **原理**：基于过程奖励模型（PRM）的得分特性（轨迹得分受限于叶节点得分），当搜索树中所有叶节点均被判定为“无效”（得分低于阈值）时，提前终止该请求。
    *   **优化**：引入“选择性无效检查”，利用第一步奖励与最终得分的相关性，排除低潜力分支，提高早停触发率。
*   **自适应增强与调度（Adaptive Boosting & Scheduling）**：
    *   **动态并行度控制**：根据任务的“资历”（等待时间）和“紧迫性”（当前最高分接近阈值的程度）计算优先级得分。
    *   **资源重分配**：将早停释放的计算资源动态分配给更有潜力的并发任务，通过增加其并行度（DOP）来加速完成，从而清理运行队列。

*   **发现**：长尾延迟主要由那些既无法触发正向早停、又在顺序执行中耗尽所有 rollout 预算的“难题”引起，负向早停是解决这一问题的关键。

#### 7. 优点
*   **系统级创新**：不只是改进搜索算法，而是从资源调度和并发管理的系统层面解决 TTCS 的落地难题。
*   **实用性强**：直接集成于主流推理框架 vLLM，对于需要实时响应的生产环境具有很高的参考价值。
*   **自适应性**：能够根据系统负载和任务进度动态调整策略，而非使用死板的固定参数。

#### 8. 不足与局限
*   **简单任务的开销**：在某些简单任务（如 AMC23 配合 Qwen 模型）中，过度并行化带来的调度开销可能导致吞吐量反而略微下降。

*   **任务领域局限**：目前主要在数学推理任务上验证，对于缺乏明确中间奖励信号的其他推理领域（如创意写作或开放式对话）的适用性有待进一步研究。
