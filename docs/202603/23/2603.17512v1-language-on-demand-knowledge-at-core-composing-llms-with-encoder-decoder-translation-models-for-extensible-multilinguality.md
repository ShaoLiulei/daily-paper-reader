## 摘要
大语言模型（LLMs）展现出强大的通用智能，但其多语言性能仍然高度不平衡。尽管 LLMs 在统一的语义空间中编码了大量的跨语言知识，但它们往往难以可靠地将这些知识与低资源或未见过的语言进行对接。幸运的是，预训练的编码器-解码器翻译模型已经具备了平衡的多语言能力，这为 LLMs 提供了天然的补充。在这项工作中，我们提出了 XBridge，这是一种组合式的“编码器-LLM-解码器”架构，它将多语言理解和生成任务卸载到外部预训练翻译模型中，同时保留 LLM 作为通用知识处理的以英语为核心的枢纽。为了解决由此产生的跨模型表示失配问题，我们引入了轻量级的跨模型映射层和基于最优传输（optimal transport）的对齐目标，从而实现了多语言生成的细粒度语义一致性。在四种 LLMs 上进行的多语言理解、推理、摘要和生成实验表明，XBridge 优于强基准模型，特别是在低资源和此前未见过的语言上，且无需对 LLM 进行重新训练。

## Abstract
Large language models (LLMs) exhibit strong general intelligence, yet their multilingual performance remains highly imbalanced. Although LLMs encode substantial cross-lingual knowledge in a unified semantic space, they often struggle to reliably interface this knowledge with low-resource or unseen languages. Fortunately, pretrained encoder-decoder translation models already possess balanced multilingual capability, suggesting a natural complement to LLMs. In this work, we propose XBridge, a compositional encoder-LLM-decoder architecture that offloads multilingual understanding and generation to external pretrained translation models, while preserving the LLM as an English-centric core for general knowledge processing. To address the resulting representation misalignment across models, we introduce lightweight cross-model mapping layers and an optimal transport-based alignment objective, enabling fine-grained semantic consistency for multilingual generation. Experiments on four LLMs across multilingual understanding, reasoning, summarization, and generation indicate that XBridge outperforms strong baselines, especially on low-resource and previously unseen languages, without retraining the LLM.

以下是对该论文的结构化总结：

### 1. 核心问题与整体含义
*   **研究动机**：尽管 LLM 具备强大的通用智能和跨语言知识，但其多语言表现极度不均衡。LLM 在英语和高资源语言上表现优异，但在低资源或未见过的语言（unseen languages）上往往无法理解或生成。
*   **核心矛盾**：LLM 的局限性不在于缺乏知识，而在于难以将这些知识与多样化的语言表示空间对接。
*   **整体思路**：利用预训练的“编码器-解码器”翻译模型（如 NLLB）作为语言接口，将多语言的理解和生成任务“外包”给翻译模型，而让 LLM 保持为以英语为核心的“知识处理引擎”。

### 2. 方法论
*   **核心架构（Encoder-LLM-Decoder）**：
    *   **多语言编码器**：将多语言输入映射到共享语义空间。
    *   **轻量级映射层（Mapping Layers）**：通过 MLP 将编码器表示转换为 LLM 的输入空间，并将 LLM 的输出隐藏状态转换为解码器的交叉注意力空间。
    *   **冻结的 LLM**：作为核心，负责逻辑推理和知识处理，训练过程中保持参数冻结。
    *   **多语言解码器**：根据 LLM 的处理结果，生成目标语言文本。
*   **关键技术：最优传输（OT）对齐**：
    *   由于 LLM 和翻译模型使用不同的分词器（Tokenizer）和表示空间，存在严重的语义失配。
    *   引入基于最优传输的对齐目标，通过计算 LLM 输出与编码器重编码表示之间的“软匹配”距离，强制实现 token 级别的语义一致性。
*   **三阶段训练策略**：
    1.  **跨模型映射**：使用三语平行数据建立编码器、LLM 和解码器之间的初步语义桥梁。
    2.  **编码器端适配**：在下游任务（如推理、摘要）上微调输入映射，增强 LLM 对多语言语义的利用。
    3.  **解码器端适配**：优化输出接口，提升多语言生成的质量和忠实度。

### 3. 实验设计
*   **基础模型**：评估了四种主流 LLM：MetaMath-7B、LLaMA3-8B、Aya-23-8B、Qwen2.5-7B-Instruct。
*   **翻译模型**：主要使用 NLLB-200-1.3B，同时也测试了 M2M100-1.2B。
*   **数据集与场景**：
    *   **翻译**：FLORES-101（涵盖高/低资源语言）。
    *   **数学推理**：MGSM。
    *   **摘要**：XL-Sum。
    *   **常识推理**：X-CSQA。
*   **对比基线**：SFT（直接多语言微调）、Translate-Test（翻译-推理-回译流水线）、MindMerger（仅增强编码器）、LayAlign（层级融合增强编码器）。

### 4. 资源与算力
*   **算力设备**：使用了 **8 台 NVIDIA H800 GPU**。
*   **训练细节**：每个阶段训练 3 个 epoch，batch size 为 128，学习率为 2e-5。
*   **参数效率**：由于 LLM 保持冻结，仅训练轻量级的映射层和解码器的交叉注意力层，参数量增加极小。

### 5. 实验数量与充分性
*   **实验规模**：论文在 4 个 LLM 骨干网络、3 大类核心任务（翻译、推理、摘要）上进行了广泛测试。
*   **语言覆盖**：重点测试了 10 种语言（含孟加拉语、斯瓦希里语等低资源语言），并进一步在 **42 种未参与训练的语言**上验证了泛化性。
*   **消融实验**：详细分析了 OT 对齐、解码器模块、三阶段策略等各组件的贡献。
*   **充分性评价**：实验设计非常全面，通过跨模型、跨任务、跨语言的对比，客观地证明了 XBridge 的有效性和通用性。

### 6. 主要结论与发现
*   **性能飞跃**：XBridge 在低资源和未见语言上的表现显著优于强基线，甚至接近专门的翻译模型水平。
*   **知识保留**：在增强多语言能力的同时，LLM 原有的英语推理能力几乎没有退化。
*   **泛化能力**：跨模型映射学习到的是语言无关的语义转换，能够直接泛化到训练集之外的语言。
*   **按需生成**：通过切换解码器的语言 token，XBridge 可以灵活地按需生成任意目标语言，表现稳定。

### 7. 优点
*   **架构优雅**：解耦了“语言能力”与“知识能力”，避免了在 LLM 内部进行昂贵且可能导致灾难性遗忘的多语言重训。
*   **可扩展性强**：只要外部翻译模型支持，LLM 就能轻松扩展到数百种语言。
*   **对齐精准**：引入最优传输解决了异构模型间 token 不对齐的顽疾，提升了生成的忠实度。

### 8. 不足与局限
*   **推理延迟**：相比于纯 LLM，增加编码器和解码器会带来额外的计算开销（虽然比“翻译流水线”快，但比单模型慢）。
*   **性能上限**：系统的多语言上限受限于所选用的翻译模型（如 NLLB）的质量。
*   **复杂性**：三阶段训练虽然稳定，但相比单阶段微调增加了流程复杂度。
