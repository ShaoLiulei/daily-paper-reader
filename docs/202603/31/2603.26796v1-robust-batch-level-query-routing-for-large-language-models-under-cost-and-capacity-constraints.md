## 摘要
我们研究了在成本、GPU 资源和并发约束下，将查询路由到大语言模型（LLM）的问题。先前的逐查询路由方法通常无法控制批处理级成本，特别是在非均匀或对抗性批处理的情况下。为解决这一问题，我们提出了一种批处理级、资源感知的路由框架，该框架在遵守成本和模型容量限制的同时，联合优化每个批次的模型分配。我们进一步引入了一种鲁棒变体，该变体考虑了预测 LLM 性能的不确定性，并结合了一种在多个模型之间平衡质量和吞吐量的离线实例分配程序。在两个多任务 LLM 基准测试上的实验表明，鲁棒性相比非鲁棒对应方法提高了 1-14% 的准确率（取决于性能估计器），在对抗性批处理下，批处理级路由比逐查询方法性能提升高达 24%，且优化后的实例分配相比非优化分配产生了高达 3% 的额外收益，同时所有方法都严格控制了成本和 GPU 资源约束。

## Abstract
We study the problem of routing queries to large language models (LLMs) under cost, GPU resources, and concurrency constraints. Prior per-query routing methods often fail to control batch-level cost, especially under non-uniform or adversarial batching. To address this, we propose a batch-level, resource-aware routing framework that jointly optimizes model assignment for each batch while respecting cost and model capacity limits. We further introduce a robust variant that accounts for uncertainty in predicted LLM performance, along with an offline instance allocation procedure that balances quality and throughput across multiple models. Experiments on two multi-task LLM benchmarks show that robustness improves accuracy by 1-14% over non-robust counterparts (depending on the performance estimator), batch-level routing outperforms per-query methods by up to 24% under adversarial batching, and optimized instance allocation yields additional gains of up to 3% compared to a non-optimized allocation, all while strictly controlling cost and GPU resource constraints.

### 成本与容量约束下大语言模型的鲁棒批处理级查询路由（Robust Batch-Level Query Routing for LLMs）论文总结

#### 1. 核心问题与整体含义（研究动机和背景）
随着大语言模型（LLM）推理成本和资源消耗的增加，**LLM 路由（Routing）**技术应运而生，旨在将简单查询分配给廉价模型，将复杂查询分配给高性能模型。然而，现有的路由方法大多基于**单查询（Per-query）**决策，存在以下缺陷：
*   **成本失控**：在实际生产中，推理系统通常采用动态批处理（Batching），单查询路由难以在批处理级别强制执行严格的预算约束，容易导致成本波动。
*   **资源忽视**：忽略了硬件容量限制（如本地 GPU 显存和并发数）与云端 API 成本之间的权衡。
*   **预测不确定性**：路由决策依赖于对模型性能的预测，但预测值往往存在噪声，导致路由失败。

#### 2. 方法论：核心思想与关键技术
论文提出了一种**批处理级、资源感知的路由框架**，主要包含三个核心组件：
*   **批处理级优化（Batch-Level Optimization）**：将路由建模为**整数线性规划（ILP）**问题。在每个批次（Batch）到达时，联合优化所有查询的模型分配，目标是最大化批次平均性能，同时满足总成本预算和各模型的硬件容量（并发数）限制。
*   **鲁棒路由（Robust Routing）**：为了应对性能预测的不确定性，引入了鲁棒优化机制。通过自助法（Bootstrap Resampling）估计预测值的置信区间，在优化目标中使用预测性能的**下界（Lower Bound）**而非点估计值，从而在最坏情况下保证性能。
*   **离线实例分配（Offline Instance Allocation）**：在推理前，通过离线优化确定本地 GPU 资源在不同模型间的最佳分配比例（即每个模型部署多少个实例），以平衡吞吐量和质量。
*   **性能估计器**：采用了 XGBoost、k-最近邻（kNN）和多维项目反应理论（MIRT）等模型来预测 LLM 对特定查询的表现。

#### 6. 主要结论与发现
*   **鲁棒性显著**：引入鲁棒性使准确率提升了 1-14%，有效降低了因预测偏差导致的性能崩溃风险。

*   **模型无关**：框架不依赖于特定的 LLM 或预测器，具有很强的扩展性。
