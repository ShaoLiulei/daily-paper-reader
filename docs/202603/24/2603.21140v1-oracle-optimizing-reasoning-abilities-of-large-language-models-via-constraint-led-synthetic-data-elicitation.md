## 摘要
使用合成推理数据训练大语言模型（LLMs）已成为增强其推理能力的流行方法，而影响这一范式有效性的关键因素是生成的逐步推理数据的质量。为了生成高质量的推理数据，许多近期的方法生成合成推理路径并根据最终答案的正确性进行过滤，这往往忽略了中间推理步骤中的缺陷。为了加强对中间推理步骤的验证，先前的工作主要求助于代码执行或符号推理引擎。然而，基于代码的验证仅限于代码或数学任务，而推理引擎则需要结构良好且完整的上下文。因此，现有方法在涉及模糊或不完整上下文的自然语言推理任务中无法有效发挥作用。在这些任务中，合成数据仍然缺乏验证每个推理步骤的可靠检查。为了应对这一挑战，我们引入了 ORACLE，这是一个受三段论推理启发的结构化数据生成框架。ORACLE 将 LLM 的生成优势与符号监督相结合：LLM 生成逐步推理上下文，而符号推理引擎验证每个中间步骤的有效性。通过采用统一的提示模板来诱导模块化推理链，ORACLE 实现了细粒度的步骤级验证，促进了高质量多步推理数据的构建。在六个逻辑、事实和常识推理基准测试中，我们的 ORACLE 在多个模型上始终优于强基准模型。

## Abstract
Training large language models (LLMs) with synthetic reasoning data has become a popular approach to enhancing their reasoning capabilities, while a key factor influencing the effectiveness of this paradigm is the quality of the generated multi-step reasoning data. To generate high-quality reasoning data, many recent methods generate synthetic reasoning paths and filter them based on final answer correctness, often overlooking flaws in intermediate reasoning steps. To enhance the verification of intermediate reasoning steps, prior work primarily resorts to code execution or symbolic reasoning engines. However, code-based validation is restricted to code or mathematical tasks, and reasoning engines require a well-structured and complete context. As a result, existing methods fail to function effectively in natural language reasoning tasks that involve ambiguous or incomplete contexts. In these tasks, synthetic data still lack reliable checks for verifying each reasoning step. To address this challenge, we introduce ORACLE, a structured data generation framework inspired by syllogistic reasoning. ORACLE integrates the generative strengths of LLMs with symbolic supervision: the LLM produces step-wise reasoning contexts, while a symbolic reasoning engine verifies the validity of each intermediate step. By employing a unified prompting template to elicit modular reasoning chains, ORACLE enables fine-grained, step-level validation, facilitating the construction of high-quality multi-step reasoning data. Across six logical, factual, and commonsense reasoning benchmarks, our ORACLE consistently outperforms strong baselines on multiple models.

训练大语言模型（LLMs）时，使用合成推理数据已成为增强其复杂推理能力的常用手段。然而，现有方法（如 RFT、Self-rewarding）主要依赖**最终答案的正确性**来过滤数据，这导致模型可能通过错误的中间步骤偶然得到正确答案（即“捷径学习”或“幻觉推理”）。虽然代码执行或符号推理引擎可以验证中间步骤，但前者局限于数学/代码领域，后者则对自然语言的模糊性和上下文完整性要求极高。
**核心问题：** 如何在缺乏标准化上下文的自然语言推理任务中，实现对合成推理数据中间步骤的可靠、细粒度验证？

### 2. 方法论：ORACLE 框架
ORACLE 受到**三段论推理（Syllogistic Reasoning）**的启发，将 LLM 的生成能力与符号推理引擎的严谨性相结合。
*   **结构化模板设计：** 强制模型按模块生成推理步骤，包括：`<QUERY>`（子问题）、`<FACTS>`（相关事实）、`<RULE>`（推理规则）、`<REVISION>`（自我修正过程）及 `<REASONING_RESULT>`（结论）。
*   **两阶段训练流程：**
    *   **阶段 1（格式内化）：** 利用少量人工示例进行 Few-shot 提示，生成初步合成数据，通过严格的格式和答案过滤后，对基座模型进行监督微调（SFT），使其掌握结构化推理格式。
    *   **阶段 2（符号监督与优化）：** 引入符号推理引擎（Pyke）作为外部验证器。
        *   **束搜索（Beam Search）：** 在生成每一步时，将自然语言翻译为符号语言并由引擎执行。
        *   **综合评分机制：** 根据引擎执行是否成功（$W_1$）、LLM 对精度的评估（$W_2$）以及 LLM 对可行性的估计（$W_3$）进行打分，筛选高质量路径。
        *   **数据产出：** 成功路径用于 SFT；将引擎验证通过的节点与其失败的兄弟节点配对，用于直接偏好优化（DPO）。

### 3. 实验设计
*   **数据集：** 涵盖六大基准测试，包括逻辑推理（ProntoQA, ProofWriter）、常识推理（BoolQ, CosmosQA, StrategyQA）和科学多跳推理（ScienceQA）。
*   **基座模型：** Llama-3.1-8B-Instruct、Mistral-7B-Instruct-v0.3、Qwen-2.5-7B-Instruct。
*   **对比方法（Baselines）：**

    *   RFT（拒绝采样过滤）

*   **消融实验：** 分别验证了“无推理引擎”、“无束搜索”和“无 DPO”的情况，证明了各组件的必要性。
*   **分析深度：** 论文还分析了推理引擎的执行成功率随训练迭代的变化，以及引擎失败的具体原因（生成错误 vs. 翻译错误），体现了实验的客观性与公平性。

### 6. 主要结论与发现
*   **性能领先：** ORACLE 在所有数据集和模型上均取得或接近最佳性能，尤其在逻辑推理任务（ProofWriter）上提升显著（最高提升约 5.7%）。
*   **验证有效性：** 符号推理引擎能有效强制逻辑一致性，减少模型在中间步骤的幻觉。
*   **迭代增益：** 随着训练迭代增加，模型生成的推理步骤更符合规范，推理引擎的执行成功率也随之提高。
*   **泛化能力：** 尽管模板基于三段论，但该方法在常识和科学推理等非纯逻辑任务中同样表现出强劲的泛化效果。

### 7. 优点
*   **细粒度验证：** 突破了仅依赖最终答案过滤的局限，实现了步骤级的过程监督。
*   **软硬结合：** 巧妙地将 LLM 的语义理解能力（处理模糊上下文）与符号引擎的逻辑严谨性（确保推理正确）结合。
*   **高解释性：** 结构化模板使推理过程透明化，便于自动提取和错误溯源。

*   **计算开销：** 阶段 2 的束搜索涉及多次 LLM 调用和引擎验证，数据生成成本高于简单的拒绝采样。
