## 摘要
基于大语言模型（LLM）的智能体依赖记忆机制来重用过去解决问题的经验知识。现有方法通常以单智能体的方式构建记忆，将存储的知识与单个模型的推理风格紧密耦合。在异构智能体的现代部署场景中，一个自然产生的问题是：单个记忆系统能否在不同模型之间共享？我们发现，在智能体之间直接迁移记忆往往会导致性能下降，因为此类记忆将任务相关知识与智能体特有的偏置纠缠在一起。为了应对这一挑战，我们提出了 MemCollab，这是一个协作记忆框架，通过对比不同智能体在同一任务上生成的推理轨迹来构建与智能体无关的记忆。这一对比过程蒸馏出了抽象的推理约束，这些约束在捕捉共享的任务级不变性的同时，抑制了智能体特有的伪影。我们进一步引入了一种任务感知检索机制，根据任务类别对记忆访问进行条件化处理，确保在推理时仅使用相关的约束。在数学推理和代码生成基准测试上的实验表明，MemCollab 在包括跨模型家族设置在内的多种智能体中，一致地提高了准确性和推理效率。我们的结果表明，协作构建的记忆可以作为多种基于 LLM 的智能体的共享推理资源。

## Abstract
Large language model (LLM)-based agents rely on memory mechanisms to reuse knowledge from past problem-solving experiences. Existing approaches typically construct memory in a per-agent manner, tightly coupling stored knowledge to a single model's reasoning style. In modern deployments with heterogeneous agents, a natural question arises: can a single memory system be shared across different models? We found that naively transferring memory between agents often degrades performance, as such memory entangles task-relevant knowledge with agent-specific biases. To address this challenge, we propose MemCollab, a collaborative memory framework that constructs agent-agnostic memory by contrasting reasoning trajectories generated by different agents on the same task. This contrastive process distills abstract reasoning constraints that capture shared task-level invariants while suppressing agent-specific artifacts. We further introduce a task-aware retrieval mechanism that conditions memory access on task category, ensuring that only relevant constraints are used at inference time. Experiments on mathematical reasoning and code generation benchmarks demonstrate that MemCollab consistently improves both accuracy and inference-time efficiency across diverse agents, including cross-modal-family settings. Our results show that the collaboratively constructed memory can function as a shared reasoning resource for diverse LLM-based agents.

### 2. 方法论
MemCollab 框架分为两个主要阶段：**对比记忆构建**和**任务感知检索推理**。

*   **核心思想**：借鉴对比学习（Contrastive Learning）的思想，通过对比同一任务下不同智能体生成的“成功”与“失败”轨迹，过滤掉模型特有的风格（Bias），蒸馏出任务级的逻辑不变性（Invariants）。
*   **关键技术细节**：
    1.  **轨迹配对与偏好选择**：对训练集中的每个任务，让两个异构智能体（如一强一弱）分别生成推理轨迹。根据结果将其分为“首选轨迹（$\tau^+$）”和“非首选轨迹（$\tau^-$）”。
    2.  **对比轨迹分析**：使用强模型作为蒸馏器，对比 $\tau^+$ 和 $\tau^-$。识别出导致失败的“违规模式（Violation Patterns）”和确保成功的“推理不变性（Reasoning Invariants）”。
    3.  **记忆条目构建**：将分析结果转化为抽象的推理约束，格式为：`(enforce [不变性]; avoid [违规模式])`。这些约束使用抽象概念（如变量隔离、案例枚举）而非具体数值。
    4.  **任务感知检索（Task-Aware Retrieval）**：
        *   **分类**：利用 LLM 将任务预先分类（如代数、数论、代码逻辑等）。
        *   **路由**：推理时，先确定查询任务的类别，仅在该类别的记忆子集中进行相似度检索，以减少噪声干扰。
    5.  **记忆增强推理**：智能体在推理时将检索到的 top-p 条约束作为 Prompt 的一部分，引导其避开已知错误并遵循正确逻辑。

### 6 主要结论与发现
*   **MemCollab 的优越性**：在所有基准测试中，MemCollab 均显著优于直接迁移记忆或单模型记忆。例如，Qwen2.5-7B 在 MATH500 上的准确率从 52.2% 提升至 67.0%。
*   **跨架构协同有效**：跨家族模型（Llama 与 Qwen）协作构建的记忆有时甚至优于同家族协作，说明对比不同架构能更好地抑制模型偏见。
*   **效率提升**：使用 MemCollab 的智能体在解决问题时所需的**推理轮数（Reasoning Turns）显著减少**，证明了记忆引导减少了盲目的试错。
*   **检索阈值**：检索过多的记忆条目（超过 3-5 条）反而会引入噪声，导致性能下降。

### 7. 优点
*   **解耦性强**：成功将“如何解决问题”的逻辑与“特定模型如何表达”的风格分离。
*   **任务感知机制**：通过先分类后检索的策略，有效解决了长上下文中的干扰问题（Lost in the Middle）。
*   **普适性**：不仅提升了弱模型的表现，也让强模型通过避开常见错误模式而变得更强。

### 8. 不足与局限
*   **构建成本**：需要针对同一任务运行多个模型来获取轨迹对，这在初期构建记忆库时存在额外的计算开销。
*   **依赖蒸馏模型**：对比分析过程依赖于一个性能较强的模型（如 32B 或更高）来总结规律，若蒸馏模型本身存在逻辑盲点，记忆质量会受限。
*   **应用范围**：目前主要集中在数学和代码等具有明确逻辑对错的任务，在创意写作或开放式对话等主观性较强的任务中效果尚待验证。
