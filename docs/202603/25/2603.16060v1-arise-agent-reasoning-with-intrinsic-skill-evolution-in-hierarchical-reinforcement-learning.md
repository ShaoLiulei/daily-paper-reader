## 摘要
提升语言模型数学推理能力的主流范式依赖于具有可验证奖励的强化学习。然而，现有方法孤立地处理每个问题实例，未能利用训练过程中出现并积累的可复用策略。为此，我们引入了 ARISE（Agent Reasoning via Intrinsic Skill Evolution），这是一个分层强化学习框架，其中共享策略既在决策高层管理技能（称为技能管理器），又在执行底层生成响应（称为执行器）。管理器通过专门的技能生成采样（rollout）对成功的解题轨迹进行结构化总结（执行后），从而维护一个分层技能库；同时采用策略驱动的选择机制检索相关技能，为后续采样提供条件（执行前）。分层奖励设计引导了推理能力与技能库质量的协同演化。在两个基座模型和涵盖竞赛数学及 Omni-MATH 的七个基准测试上的实验表明，ARISE 一贯优于 GRPO 系列算法和记忆增强基线，在分布外任务上的提升尤为显著。消融研究证实，各组件均对性能提升有所贡献，且技能库质量与推理性能在训练过程中同步提升。代码见 https://github.com/Skylanding/ARISE。

## Abstract
The dominant paradigm for improving mathematical reasoning in language models relies on Reinforcement Learning with verifiable rewards. Yet existing methods treat each problem instance in isolation without leveraging the reusable strategies that emerge and accumulate during training. To this end, we introduce ARISE (Agent Reasoning via Intrinsic Skill Evolution), a hierarchical reinforcement learning framework, in which a shared policy operates both to manage skills at high-level and to generate responses at low-level (denoted as a Skills Manager and a Worker, respectively). The Manager maintains a tiered skill library through a dedicated skill generation rollout that performs structured summarization of successful solution traces (after execution), while employing a policy-driven selection mechanism to retrieve relevant skills to condition future rollouts (before execution). A hierarchical reward design guides the co-evolution of reasoning ability and library quality. Experiments on two base models and seven benchmarks spanning both competition mathematics and Omni-MATH show that ARISE consistently outperforms GRPO-family algorithms and memory-augmented baselines, with particularly notable gains on out-of-distribution tasks. Ablation studies confirm that each component contributes to the observed improvements and that library quality and reasoning performance improve in tandem throughout training. Code is available at \href{https://github.com/Skylanding/ARISE}{https://github.com/Skylanding/ARISE}.

### 1. 核心问题与研究动机
*   **核心问题**：当前的语言模型数学推理强化学习（如 DeepSeek-R1 使用的 GRPO）通常孤立地处理每个题目。一旦采样结束，过程中产生的成功解题策略（Skills）就会被丢弃，无法在后续训练中积累和复用。
*   **研究动机**：现有的“记忆增强”方法通常依赖外部检索器，导致技能管理与策略优化脱节。作者希望构建一个**内在技能演化机制**，让模型在提升推理能力的同时，自主构建、筛选和进化一套可复用的技能库。

### 2. 方法论：ARISE 框架
ARISE 采用**分层强化学习（HRL）**架构，将单一策略网络 $\pi_\theta$ 同时作为“管理器（Manager）”和“执行器（Worker）”：
*   **核心思想**：将技能库视为智能体状态的一部分，通过策略梯度同时优化解题能力和技能选择偏好。
*   **关键技术细节**：
    *   **分层策略**：管理器在解题前根据查询（Query）与技能的条件对数概率（Log-probability）进行评分并选择技能；执行器根据选定技能生成解题步骤。
    *   **技能生成（Upload）**：在标准采样之外增加一个 $O_{G+1}$ 采样，专门用于将该组中成功的解题轨迹总结为结构化的 JSON 技能文档。
    *   **两层库架构**：维护一个高频调用的“缓存区（Cache）”和一个大容量的“储备库（Reservoir）”，通过五种操作（添加、更新、驱逐、加载、删除）动态维护技能质量。
    *   **分层奖励设计**：设置 $r_2$（使用技能且正确）、$r_1$（未使用技能但正确）和 $r_0$（错误）。通过 $r_2 > r_1 > r_0$ 的设计，利用组相对优势（Group-relative advantage）迫使模型学习如何有效利用技能。
*   **训练流程**：分为两个阶段。第一阶段（Warm-up）仅进行基础强化学习并初步填充技能库；第二阶段激活全流程，进行技能驱动的联合优化。

### 3. 实验设计
*   **基座模型**：Qwen3-4B-Instruct-2507 和 Phi-4-mini-instruct (3.8B)。
*   **训练数据集**：DeepScaleR 数据集（约 4 万个数学题目，涵盖 AMC、AIME、MATH 等）。
*   **Benchmark**：
    *   **分布内（In-distribution）**：AMC 23、AIME 24、AIME 25。
    *   **分布外（OOD）**：Omni-MATH（包含代数、数论、组合、几何四个领域）。
*   **对比方法**：
    *   **GRPO 家族**：原生 GRPO、Dr.GRPO、DAPO、GSPO。
    *   **记忆/技能增强类**：EvolveR、SimpleMem、SkillRL。

### 4. 资源与算力
*   **硬件环境**：使用了 **8 张 NVIDIA A100-80GB GPU**。
*   **训练参数**：训练步数为 2000 步，组大小（Group Size）$G=8$。
*   **开销分析**：相比原生 GRPO，ARISE 增加了约 16.6% 的训练耗时（主要来自技能评分和额外的 $O_{G+1}$ 采样），但在推理时的 Token 开销仅增加约 3%。

### 5. 实验数量与充分性
*   **实验规模**：在两个不同架构的基座模型上进行了完整测试，涵盖了 7 个主流数学基准。
*   **消融实验**：非常充分。作者分别验证了分层奖励、随机选择、移除技能生成、移除置信度门控等变体对性能的影响。
*   **客观性**：所有结果均基于 32 次独立运行的 Pass@1 平均值，并进行了超参数敏感性分析（如缓存大小、预热步数等），实验设计严谨、公平。

### 6. 主要结论与发现
*   **性能领先**：ARISE 在所有基准测试中均优于 GRPO 系列和现有的记忆增强方法。
*   **OOD 泛化极强**：在 Omni-MATH 上的提升尤为显著（最高提升 2.9%），说明演化出的技能库有助于模型处理未见过的复杂奥数题。
*   **协同演化**：实验观察到技能库的质量与模型的推理准确率同步增长。在训练后期，准确率的提升更多来自于模型对现有技能的“精准选择”，而非技能库规模的无限扩张。

### 7. 优点（亮点）
*   **内生性（Intrinsic）**：技能选择不再依赖外部检索模型，而是由策略网络自身驱动，实现了端到端的优化。
*   **高效性**：通过两层缓存机制和严格的 JSON Schema 约束，在极小的 Token 开销下实现了显著的性能增益。
*   **自适应性**：分层奖励机制巧妙地解决了“模型为何要使用技能”的动力问题。

### 8. 不足与局限
*   **任务局限性**：目前仅在数学推理任务上进行了验证。对于代码生成或多工具调用等任务，技能的形式（如可执行函数）可能需要进一步调整。
*   **计算开销**：虽然相比推理增益而言开销可控，但额外的 $O_{G+1}$ 采样和技能评分环节仍增加了训练初期的算力门槛。
*   **偏差风险**：如果初始种子技能或早期生成的技能存在逻辑偏差，可能会通过强化学习过程产生一定的负面反馈循环（尽管实验中未观察到此现象）。
